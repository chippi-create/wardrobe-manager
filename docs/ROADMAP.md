# ロードマップ

このアプリの今の状態と、これからの方針のメモです。

## 今の状態（段階1：端末内保存）

- 公開URL：https://wardrobe-manager.cps-create.workers.dev
- 公開方法：Cloudflare Workers（静的アセットのみ）。GitHub の `main` にプッシュすると自動で反映される
- データの保存先：使う人の端末のブラウザ（IndexedDB）だけ。サーバーには送らない
- できること：服の登録、メルカリと同じカテゴリ分け、出品用文章の作成、コーデ作成、気温とシーンからのコーデ提案、着用記録、家族のメンバー切り替え、バックアップの書き出し・読み込み

## 次の段階（段階2：ログインとクラウド同期）

しばらく段階1のまま使ってから着手する。

### 決まっていること

- **サービス**：Supabase（無料枠）で、ログイン・データベース・写真の保存をまかなう
  - 無料枠の目安：写真などのファイル 1GB、データベース 500MB、月5万ユーザー
  - 1週間アクセスがないとプロジェクトが一時停止する（再開は可能）
  - 着手するときに、最新の無料枠の条件を確認する
- **ログイン方法**：メールアドレス（パスワードなし、リンクまたはコード）と Google アカウント
  - Apple でサインインは、Apple Developer Program（有料）が必要なので見送り
  - メールの送信には Supabase 標準の送信機能を使うと送信数の制限が厳しいため、本番では Resend などの送信サービスの設定を検討する
- **家族の共有**：家族で1つのアカウントを共有する。今の「メンバー切り替え」の仕組みをそのまま使う
- **写真**：クラウドに保存して、iPhone の容量をほとんど使わないようにする。ファイルが 1GB を超えそうになったら、写真だけ Cloudflare R2（10GBまで無料）に移すことを検討する

### 進め方

1. 利用者が Supabase のアカウントとプロジェクトを作る
2. データベースのテーブルと行レベルセキュリティ（RLS）の SQL を用意し、Supabase の SQL Editor で実行してもらう
   - 自分のアカウントのデータしか読み書きできないようにする
   - 写真のストレージも同じようにアカウントごとに分ける
3. アプリにログインと同期を追加する
   - アプリには Supabase の公開用キー（anon key）だけを入れる。秘密のキー（service_role key）は絶対に入れない
   - 端末内の IndexedDB は、オフラインでも見られるように一時保存として残す
4. 段階1で端末に保存してあるデータを、ログイン後にクラウドへ移せるようにする（登録し直さなくて済むように）

## そのほかのメモ

- メルカリのカテゴリ一覧（`js/categories.js`）は知識をもとに作ったもので、実際の出品画面とはまだ照らし合わせていない。違いが見つかったら更新する
- メルカリには個人向けの出品APIがないため、自動出品はできない。出品用の文章をコピーして貼り付ける方式にしている
- アプリを更新したら `sw.js` の `CACHE` のバージョンを上げる
